## 1. `UCIException` → `CalError` + `CalResult<T>`

Rust eliminates exceptions entirely. The equivalent is a structured error type returned in `Result<T, CalError>`:

```rust
// C++ (avoid):    void write(msg) throws UCIException;
// Rust CAL idiom:
fn write(&mut self, msg: &dyn CalMessage) -> CalResult<()>
```

`CalErrorKind` is a `#[non_exhaustive]` enum covering every mandatory error condition in the spec (§5.1.2, Table 5.9-2): `TopicUnavailable`, `AsbFailed`, `UuidConformanceError`, `AbstractInstantiation`, etc. The `#[non_exhaustive]` attribute is important — it allows future spec revisions to add error kinds without breaking existing client code.

---

## 2. `CalUuid` — Enforcement by Construction (§5.2.3)

Rather than a separate validation function (which could be forgotten), `CalUuid` makes it **structurally impossible** to hold an invalid UUID:

- All construction paths run through a private `validate()` function
- Enforces **Variant 1 (Leach-Salz)** — CERT CAL-016479
- Enforces **Version 1, 3, or 4** — CERT CAL-005181
- `parse()` returns `CalResult<CalUuid>`, not a raw UUID

`ServiceUuids` aggregates the system/service/subsystem/component/capability UUIDs required by CERT CAL-005203.

---

## 3. Accessor Traits — Idiomatic Rust field access

The generated C++ accessor methods (`get_xxx()`, `has_xxx()`, `set_xxx()`, `clear_xxx()`) become **traits** in Rust:

| C++ Pattern | Rust Trait | Key Behavior |
|---|---|---|
| Required field getters/setters | `RequiredField<T>` | Always present |
| `has_xxx()` / `set_xxx()` / `clear_xxx()` | `OptionalField<T>` | Wraps `Option<T>`; disabled at creation (CERT CAL-005254) |
| Vector-style bounded arrays | `BoundedListField<T>` | Empty at creation (CERT CAL-005264); enforces max bound |
| Union-style choice | `ChoiceField<V>` | Uninitialized at creation (CERT CAL-005267); V = generated enum |

`CalMessage` and `CalSubMessage` are marker traits — the type system enforces that sub-messages cannot be independently published (§5.5).

---

## 4. `AbstractServiceBus` Trait (§4.12, §5.3, §5.9)

This is the central CAL instance interface. Key design choices:

- **`Box<dyn AbstractServiceBus>`** — decouples clients from implementation, matching the C++ pure-abstract class pattern
- **`CalInstanceFactory`** — a `fn` type pointer that serves as the platform's factory entry point (CERT CAL-005201)
- **Dual status interface** — `connection_status()` for polling; `register_status_listener()` for callbacks (§5.9)
- **`AsbConnectionState::validate_transition()`** — the Figure 5.9-2 state machine rules are enforced in code, not just documentation. Terminal `Failed` state is explicitly handled.
- CERT CAL-016366 (immediate callback on registration) is documented as a contract on the trait method.

---
